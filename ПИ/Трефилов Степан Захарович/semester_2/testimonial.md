# Отзыв научного руководителя о прохождении практики

**Вид практики:** Учебная, форма «Решение»
**Обучающий(ая)ся:** Трефилов Степан Захарович
**Тема практики:** Реализация универсального компиляторного интерфейса на основе JVMCI

---

Трефилов Степан Захарович в ходе прохождения практики выполнил следующие задачи:

- обзор JIT-компиляторов HotSpot (C1 и C2) и существующих интерфейсов взаимодействия с ними, включая JVMCI и Cloud Native Compiler;
- сравнительный анализ языков описания данных (JSON, Protobuf, Cap'n Proto, Flatbuffers) и обоснованный выбор протокола сериализации с упором на отсутствие копирования при передаче больших объёмов данных;
- разработка описания интерфейса на языке Cap'n Proto с определением идентификаторов сущностей окружения компиляции;
- реализация компиляторного агента для трёх целевых версий OpenJDK и C++-библиотеки, десериализующей описание окружения в объектную модель, близкую к используемой в C1 и C2;
- апробация интерфейса: компилятор-заглушка, тестовая обёртка (интерпретация, компиляция в C1 для заданного профиля, OSR-компиляция), дамп окружения и порядка трёхсот автоматических тестов с проверкой через LLVM FileCheck.

В ходе работы обучающийся эпизодически взаимодействовал с руководителем, задачи выполнял своевременно, проявлял полную самостоятельность, замечания учитывал оперативно. Собственная тестовая инфраструктура — компилятор-заглушка, управляющие обёртки и проверка через FileCheck — выполнена на уровне, заметно превышающем обычный уровень практики.

К работе имеются следующие замечания:

1. При описании целевых версий допущены фактические неточности: Foreign Function and Memory API в JDK 17 отсутствует, а поддержка Java 8 противоречит собственному изложению материала, поскольку JVMCI появился только в JDK 9. Выбор версий стоит либо обосновать, либо пересмотреть.
2. Ни ссылки на исходный код решения, ни указания на порядок сборки и запуска в отчёте нет, что затрудняет проверку результата. Там, где речь идёт о доработке HotSpot, такая ссылка необходима.
3. В разделе «Апробация» указано, что написано порядка трёхсот тестов, но не приведено ни одного результата прогона и не сказано, какая доля тестов проходит; для такой работы это ключевая характеристика.
4. В формулировке «не для самых свежих версий OpenJDK данный интерфейс является заброшенным» смысл перевёрнут. Обзорная часть отчёта в значительной мере перенесена из отчёта по предыдущей практике без указания на повтор, из-за чего объём собственного результата выглядит меньше, чем он есть на самом деле.
5. Текст не вычитан: «существуют ряд компаний», «В версиях ниже JVMCI отличается еще более существенно», «алгоритм подключения компиляторного агента может существенно отличатся», «Большую часть кода агенты для 3 версий Java разделяют», «аппробация», «диагрмма на Рис. 6», в библиографии — «Protocol Bruffers документация».
