# Отзыв научного руководителя о прохождении практики

**Вид практики:** Учебная, форма «Решение»
**Обучающий(ая)ся:** Юсуп Амин Турмуди
**Тема практики:** Реализация OAuth 2.0 в основной системе электронных денег в соответствии со стандартами BI SNAP

---

Юсуп Амин Турмуди в ходе прохождения практики выполнил следующие задачи:

- обзор традиционных способов аутентификации при обращении к API и принципов использования JWT, включая разбор состава и срока действия токена;
- выявление ограничений классического OAuth 2.0 (B2B-сценарий, отсутствие рефреш-токенов, проблема передачи секрета клиента) и обоснование перехода к модели токенов по стандарту BI SNAP;
- выбор инструментария для серверной части (javax.servlet как базовый API и Jetty Client) с разбором факторов выбора;
- проработка сценариев выдачи B2B-токена и B2B2C-токена в терминах требований BI SNAP и построение соответствующих диаграмм последовательности;
- разработка модели базы данных для сервера OAuth 2.0.

В ходе работы обучающийся эпизодически взаимодействовал с руководителем, задачи выполнял своевременно, но проявлял ограниченную самостоятельность: содержательные технические решения практически всегда ожидали внешнего направления.

Основная работа по теме в отчёте сделана, однако её глубина существенно меньше, чем следует из постановки задачи:

1. Раздел, названный «Подробности реализации», не содержит реализации: в нём нет ни классов, ни эндпоинтов, ни конкретных запросов и ответов — только пересказ требований BI SNAP и диаграммы последовательности. Это самый серьёзный недочёт работы: заявленная в названии «Реализация OAuth 2.0» в отчёте отсутствует.
2. Задачи сквозного end-to-end тестирования и валидации безопасности и эффективности решения, сформулированные в разделе «Постановка задачи», не выполнены: в отчёте нет ни описания тестов, ни результатов измерений, ни разбора сценариев контроля доступа по scope.
3. Утверждение о том, что «система OAuth 2 была развернута в промышленной среде компании PT Duta Teknologi Kreatif», ничем не подтверждено: ни описания развёртывания, ни конфигурации, ни стенда; название компании впервые появляется только в заключении.
4. Модель базы данных ограничена одним абзацем и одним рисунком; сущности, поля, типы и ограничения не описаны. Сборка набора критериев выбора технологии сорвана в одну строку, а `javax.servlet` последовательно назван фреймворком, хотя это спецификация API.
5. Сравнение с готовыми решениями (Keycloak, Spring Security OAuth2 Resource Server) не проведено, хотя именно этот вопрос определяет целесообразность собственной разработки. Упоминание Implicit flow дано без оговорки о том, что этот механизм признан устаревшим ещё в OAuth 2.1.
6. Текст и библиография не вычитаны: название стандарта записано тремя способами (BI-SNAP, BI SNAP, SNAP), расшифровка аббревиатуры дана в двух версиях, встречаются «удостоверяется, что срок действия», «необходимо работать модель базы данных», «OAuth 2» вместо OAuth 2.0, неверное название профильной организации Индонезии.

Тем не менее выбор темы и предпринятый анализ требований стандарта BI SNAP показывают, что обучающийся понимает предметную область, а не просто пересказывает учебник; вопросы на защите по существу задачи задавать осмысленно.

Рекомендую аттестовать положительно, прохождение практики по шкале ECTS оценить **не выше C**.
