# Отзыв научного руководителя о прохождении практики

**Вид практики:** Производственная, форма «Решение»
**Обучающий(ая)ся:** Юсуп Амин Турмуди
**Тема практики:** Реализация OAuth 2.0 в основной системе электронных денег в соответствии со стандартами BI SNAP

---

Юсуп Амин Турмуди в ходе прохождения практики выполнил следующие задачи:

- анализ требований к защите API применительно к схемам выдачи токенов по стандарту BI SNAP;
- обоснование выбора Spring Framework и Spring Authorization Server как инструментария сервера OAuth 2.0;
- переработка модели базы данных сервера OAuth 2.0 с учётом сокращённого набора прав доступа;
- уточнение объектной модели запросов сервера OAuth 2.0.

В ходе работы обучающийся взаимодействовал с руководителем эпизодически, задачи выполнял формально: изменения по замечаниям вносились в текст, но новое содержание при этом не появлялось.

К работе имеется ряд существенных замечаний:

1. Отчёт практически на четыре пятых воспроизводит отчёт по предыдущей практике: дословно совпадают введение, постановка задачи, обзор JWT, описание решения и раздел «Подробности реализации», приведены те же самые рисунки. Тема практики при этом не изменилась, то есть вместо нового этапа работы обучающийся представил переработанную копию предыдущего отчёта; в чём именно состоит новый результат, из отчёта установить нельзя.
2. Собственный результат семестра оказался меньше предыдущего: единственный технически содержательный раздел предыдущего отчёта (обоснование выбора конкретных библиотек и классов) удалён, а новый раздел о Spring Authorization Server не сопровождается ни одной строкой кода, ни описанием конфигурации, ни ссылкой на проект.
3. Заключение относит саму реализацию к следующему этапу практического обучения, тогда как работа называется «Реализация OAuth 2.0». По существу выполнены только проектирование базы данных и анализ требований, то есть объём сделанного по сравнению с предыдущей практикой уменьшился.
4. Титульный лист объявляет производственную практику, а заключение говорит о выполнении задач «в ходе учебной практики»; вид практики в отчёте противоречит сам себе, причём заключение начинается тремя вводными предложениями подряд, из которых два взаимно исключают друг друга.
5. Утверждение, что «Spring Authorization Server является частью Spring Framework», фактически неверно: это самостоятельный проект. Сравнение «с коммерческими open-source решениями» некорректно по смыслу, а источник, приведённый под этим утверждением, — документация самого Spring Authorization Server.
6. В библиографии у двух новых источников в поле автора стоит слово «teams», один адрес указывает на несуществующий URL (в `microservices-vsmonolith` пропущено дефисное `vs-monolith`), название профильной организации искажено. Всё это вместе с унаследованными от предыдущего отчёта опечатками показывает, что текст правился точечно, а не вычитывался.

Следует отметить, что сам выбор темы и разбор требований BI SNAP оформлены аккуратно, а формулировка о необходимости выделения этапа проектирования в отдельную работу свидетельствует о верном понимании того, что тема слишком велика для одной практики. Именно поэтому столь буквальное воспроизведение предыдущего отчёта выглядит не результатом нехватки времени, а сознательным решением ограничить объём.
